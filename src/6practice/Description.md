# Анализ бинарного ELF-файла `exec_file`

## Базовый анализ файла

Для первичного осмотра бинарного файла использовалась стандартная утилита `file`.

### Команда:
```bash
file exec_file
```

### Результат выполнения:
```text
exec_file: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=404c4d3a12baf4d6fac6f257df6a0549732b6983, for GNU/Linux 3.2.0, not stripped
```

### Анализ результатов:
*   **`ELF 64-bit`**: Файл использует 64-битную структуру формата ELF. Программа создана для работы в 64-битной операционной системе.
*   **`LSB executable`**: Использован порядок байт **Little-endian** (младший байт записывается первым).
*   **`x86-64`**: Бинарный файл скомпилирован под архитектуру процессоров Intel/AMD.
*   **`dynamically linked`**: Программа использует динамическое связывание. Это значит, что функции (такие как `printf`) будут загружаться из внешних системных библиотек в момент запуска.
*   **`not stripped`**: Файл содержит отладочные символы и имена функций (`main`, `global_status` и др.), что делает его доступным для детального анализа.

## Анализ заголовка ELF (ELF Header)

Для просмотра «паспорта» бинарного файла использовалась утилита `readelf` с флагом `-h` (header).

### Команда:
```bash
readelf -h exec_file
```

### Результат выполнения:
```text
ELF Header:
  Magic:   7f 45 4c 46 02 01 01 00 00 00 00 00 00 00 00 00 
  Class:                             ELF64
  Data:                              2's complement, little endian
  Version:                           1 (current)
  OS/ABI:                            UNIX - System V
  ABI Version:                       0
  Type:                              EXEC (Executable file)
  Machine:                           Advanced Micro Devices X86-64
  Version:                           0x1
  Entry point address:               0x400380
  Start of program headers:          64 (bytes into file)
  Start of section headers:          10528 (bytes into file)
  Flags:                             0x0
  Size of this header:               64 (bytes)
  Size of program headers:           56 (bytes)
  Number of program headers:         13
  Size of section headers:           64 (bytes)
  Number of section headers:         32
  Section header string table index: 31
```

### Анализ ключевых полей заголовка:
*   **`Magic: 7f 45 4c 46...`**: Первые байты файла. Сигнатура `7f` и символы `E`, `L`, `F` подтверждают операционной системе правильность формата.
*   **`Type: EXEC (Executable file)`**: Указывает, что данный файл является готовой к запуску программой (в отличие от библиотек `.so` или объектных файлов `.o`).
*   **`Entry point address: 0x400380`**: Точка входа в программу. При запуске файла управление передается на этот адрес памяти (здесь находится системная функция `_start`).
*   **`Size of this header: 64 (bytes)`**: Размер самого заголовка ELF составляет ровно 64 байта.
*   **`Number of program headers: 13`**: Файл разделен на 13 сегментов, которые описывают, как именно операционная система должна проецировать бинарник в оперативную память.
*   **`Number of section headers: 32`**: Внутри файла находится 32 логические секции (код, данные, таблицы символов).

## Исследование таблицы символов

С помощью утилиты `nm` была извлечена таблица символов, которая содержит имена всех внутренних переменных, функций и их адреса.

### Команда:
```bash
nm exec_file
```

### Ключевые строки из результата:
```text
0000000000403008 D __data_start
000000000040300c D global_status
                 U __libc_start_main@GLIBC_2.34
0000000000400466 T main
                 U printf@GLIBC_2.2.5
0000000000400380 T _start
```

### Анализ результатов:
*   **`000000000040300c D global_status`**: Наша глобальная переменная успешно найдена. Флаг **`D`** указывает на секцию `.data` (инициализированные глобальные данные). Переменная расположена по виртуальному адресу `0x40300c`.
*   **`0000000000400466 T main`**: Главная функция программы на Си. Флаг **`T`** означает секцию `.text` (исполняемый код). Она находится по адресу `0x400466`.
*   **`0000000000400380 T _start`**: Системная точка входа. Именно она подготавливает окружение и затем вызывает нашу функцию `main`.
*   **`U printf@GLIBC_2.2.5`**: Флаг **`U`** (Undefined) означает, что функция `printf` не встроена в этот файл, а запрашивается из внешней библиотеки `glibc`.

## Дизассемблирование и анализ кода функции `main`

Для перевода машинного кода (нулей и единиц) в человекочитаемый язык ассемблера использовался дизассемблер `objdump` с флагом `-d` (disassemble).

### Команда:
```bash
objdump -d exec_file
```
